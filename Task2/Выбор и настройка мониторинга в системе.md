# Мотивация

Внедрение мониторинга позволит выявить места ошибок, время пиковых нагрузок и медленнные операции, что, в свою очередь, позволит принять меры, обеспечивающие бесперебойность и высокую скорость работы системы. 

# Выбор подхода к мониторингу

Для баз данных и хранилища (Shop DB, MES DB, S3) необходимо использовать метод USE для отслеживания загруженности.

Для сервисов, предоставляющих API - четыре золотых сигнала. Позволит отследить просадки в производительности в зависимости от степени нагруженности запросами.

# Метрики

## Базы данных, хранилище

### Size of S3 storage

- Позволяет отследить степень заполненности и вовремя принять решение о выделении дополнительного пространства.
- Лейблы не требуются

### Size of shop db instance

- Позволяет отследить степень заполненности и вовремя принять решение о выделении дополнительного пространства.
- Лейблы не требуются

### Size of MES db instance

- Позволяет отследить степень заполненности и вовремя принять решение о выделении дополнительного пространства.
- Лейблы не требуются

### Number of requests (RPS) for shop db instance

- Позволяет отследить возросшую нагрузку со стророны сервисов и принять решеие о оптимизации запросов/горизонтальном масштабировании.
- app (с какого сервиса пришел запрос), db (в какую базу), table (в какую таблицу)

### Number of requests (RPS) for MES db instance

- Позволяет отследить степень заполненности и вовремя принять решение о выделении дополнительного пространства.
- app (с какого сервиса пришел запрос), db (в какую базу), table (в какую таблицу)
